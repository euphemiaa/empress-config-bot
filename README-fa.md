# 👑 امپرس | ربات کانفیگ رایگان V2RayNG + NPV Tunnel

ربات خودکاری که **بدون سرور و کاملاً رایگان** روی **GitHub Actions** کار می‌کند:
کانفیگ‌های سالم V2Ray را از منابع عمومی می‌گیرد، با تست TCP سالم‌ها را جداسازی می‌کند و
**هر ۹۰ دقیقه یک پست ۸ کانفیگی (۶ تا بهترین VLESS + ۲ کانفیگ از بقیه پروتکل‌ها + فایل پیوست)**
را با تاریخ شمسی و فوتر امپرس در کانال [امپرس | کانفیگ رایگان V2RayNG](https://t.me/EmpressConfig) پست می‌کند.
پست‌ها برای هر دو اپ **v2rayNG** و **NPV Tunnel** راهنمای ایمپورت دارند و دکمه «📌 آموزش اتصال» به
[پست آموزشی پین‌شده](https://t.me/EmpressConfig/21) وصل است.

> الگوی همین پروژه قبلاً برای کانال پروکسی MTProto (@EmpressProxy) ساخته شده و همین الگو برای کانفیگ‌های V2Ray پیاده شده است.

## 🧭 نحوه کار (معماری)

```
 منابع عمومی گیت‌هاب (۱۰ فایل سابسکریپشن)
        │  دانلود + دیکود base64 در صورت نیاز
        ▼
 پارس لینک‌های vmess / vless / trojan / ss  (فقط پایتون استاندارد)
        │  استخراج host و port از هر کانفیگ
        ▼
 فیلتر اولیه: تست TCP با ۱۲۰ ورکر و تایم‌اوت ۳ ثانیه  (هر host:port فقط یک بار)
        │
        ▼
 امتیاز «ایران‌پسند بودن»: Reality و پشت‌کلادفلر و TLS بالا، IP خام پورت ۸۰ پایین
        │
        ▼
 🔥 تست واقعی با موتور Xray: برای ۳۰۰ کاندیدای برتر یک پروسهٔ xray + پروکسی SOCKS لوکال
        │  بالا می‌آید، تونل کامل پروتکل بسته می‌شود و HTTP واقعی از داخل تونل رد می‌شود
        │  ← کانفیگ‌های «پورت باز ولی مُرده» (همان‌هایی که در ایران تایم‌اوت می‌دهند) حذف
        ▼
 حذف تکراری‌های پست‌شده ← حافظه state/posted.json
        │
        ▼
 انتخاب ۸ کانفیگ: اول ۶ تا بهترین VLESS، بعد ۲ تا از بقیه پروتکل‌ها
        │
        ▼
 پست فارسی چندکانفیگی سبک flyv2ray (بلوک‌های شماره‌دار + راهنمای v2rayNG و NPV Tunnel
 + لینک دانلود اپ‌ها + دکمه «📌 آموزش اتصال» و «📡 ساب کامل») → ارسال با Bot API
        │
        ▼
 فایل پیوست Empress-Configs.txt (هر خط = یک کانفیگ؛ ریپلای به پست) → sendDocument
        │
        ▼
 کامیت state با پیام [skip ci]
```

## 🚀 راه‌اندازی قدم‌به‌قدم

### گام ۱ — ساخت ریپو و آپلود فایل‌ها

1. وارد گیت‌هاب شو و با دکمه **New** یک ریپو جدید بساز (نام مثلاً `empress-config-bot`). می‌تواند **Private** باشد؛ مشکلی پیش نمی‌آید.
2. فایل‌های `main.py`، `README-fa.md` و `.gitignore` را با **Add file → Upload files** آپلود کن.
3. پوشه `.github` را نمی‌توان مستقیم آپلود کرد؛ پس: **Add file → Create new file** و در کادر نام فایل این مسیر را دقیق تایپ کن:
   ```
   .github/workflows/post.yml
   ```
   بعد محتوای فایل `post.yml` را Paste کن و **Commit changes** بزن.
4. فایل `state/posted.json` را هم با همان روش (Create new file با مسیر `state/posted.json`) بساز و محتوای آن را Paste کن.

> ⚠️ مسیر `.github/workflows/post.yml` باید دقیقاً همین باشد وگرنه گیت‌هاب ورک‌فلو را نمی‌شناسد.

### گام ۲ — ساخت بات در BotFather

1. در تلگرام به [@BotFather](https://t.me/BotFather) برو.
2. بفرست: `/newbot`
3. یک نام بده (مثلاً `EmpressConfig`) و بعد یک یوزرنیم که به `bot` ختم شود.
4. توکن (رشته‌ای شبیه `123456:ABC-...`) را کپی و جایی امن نگه دار.
   - بات تو همین الان ساخته شده: **@EmpressConfigBot** ✅ (توکنش را خودت داری)

### گام ۳ — ادمین کردن بات در کانال  ⚠️ مهم‌ترین قدم

> 🔴 **بات نمی‌تواند خودش عضو کانال شود!** حتماً باید دستی ادمینش کنی، وگرنه با خطای `403` روبرو می‌شوی.

1. وارد کانال `EmpressConfig` شو → **Manage Channel → Administrators → Add Admin**.
2. یوزرنیم بات (`@EmpressConfigBot`) را جستجو و انتخاب کن.
3. فقط و فقط حق **Post Messages** کافی است. ذخیره کن.

### گام ۴ — ساخت ۳ سکرت در گیت‌هاب

در ریپو: **Settings → Secrets and variables → Actions → New repository secret**

| نام سکرت | مقدار |
|---|---|
| `BOT_TOKEN` | توکن بات از BotFather |
| `CHANNEL_ID` | `@EmpressConfig` (چون کانالت پابلیک است همین کافی است) |
| `CHANNEL_LINK` | `https://t.me/EmpressConfig` |

> نام‌ها را دقیقاً با همین حروف بزرگ بنویس. ورک‌فلو فقط همین ۳ اسم را می‌خواند.

### گام ۵ — اولین اجرای دستی با DRY_RUN (بدون ارسال به کانال)

1. در ریپو برو به تب **Actions** → از منوی چپ **«امپرس | پست کانفیگ‌ها»** را انتخاب کن.
2. دکمه **Run workflow** را بزن → تیک گزینه **«فقط پیش‌نمایش (dry_run)»** را بزن → **Run workflow**.
3. روی ران در حال اجرا کلیک کن و لاگ مرحله «اجرای ربات» را ببین.
4. در لاگ دنبال خط `────── پیش‌نمایش قابل‌خواندن ──────` بگرد؛ دقیقاً همان متنی است که در پست واقعی خواهی دید.
5. در این حالت **هیچ‌چیز به کانال ارسال نمی‌شود** و `posted.json` هم تغییر نمی‌کند.

### گام ۶ — اجرای واقعی

همان مسیر بالا، ولی این بار **بدون تیک dry_run**. پست در کانال می‌رود و:
- آثار کانفیگ‌های پست‌شده در `state/posted.json` ذخیره و با پیام `به‌روزرسانی state [skip ci]` کامیت می‌شود.
- پست را **Pin** کن که بالای کانال بماند.

## ⏰ زمان‌بندی

ورک‌فلو **هر ۹۰ دقیقه** اجرا می‌شود = **۱۶ پست در روز** (دو خط کرون؛ یکی دقیقه ۲۳ و یکی دقیقه ۵۳):

| ساعت‌های تهران (هر روز) |
|---|
| ۰۰:۵۳ · ۰۲:۲۳ · ۰۳:۵۳ · ۰۵:۲۳ · ۰۶:۵۳ · ۰۸:۲۳ · ۰۹:۵۳ · ۱۱:۲۳ |
| ۱۲:۵۳ · ۱۴:۲۳ · ۱۵:۵۳ · ۱۷:۲۳ · ۱۸:۵۳ · ۲۰:۲۳ · ۲۱:۵۳ · ۲۳:۲۳ |

دو نکته مهم و طبیعی:
- **زمان‌بند گیت‌هاب دقیق نیست**: ممکن است چند دقیقه دیرتر اجرا شود یا در ساعات شلوغ بعضی ران‌ها کلاً drop شوند. به همین دلیل دقیقه ۰ نگذاشتیم و dedupe داریم که اگر ران دیر کرد، پست تکراری نرود.
- اگر خواستی فاصله را کم/زیاد کنی، فقط دو خط `cron` در `post.yml` را تغییر بده (دقت کن ساعت‌ها بر اساس UTC هستند). مثلاً برای هر ۳ ساعت فقط خط دوم را حذف کن.

## 🩺 عیب‌یابی

| خطا در لاگ | علت | راه‌حل |
|---|---|---|
| `HTTP 401: Unauthorized` | توکن بات اشتباه است | سکرت `BOT_TOKEN` را از BotFather دوباره چک/جایگزین کن |
| `HTTP 403: ... not enough rights` | بات ادمین نشده یا حق پست ندارد | گام ۳ را کامل کن (Post Messages) |
| `HTTP 400: chat not found` | `CHANNEL_ID` غلط است | برای کانال پابلیک همان `@EmpressConfig` را بگذار |
| `Can't parse entities` | خطای HTML در متن | رخ نمی‌دهد چون لینک‌ها escape می‌شوند؛ اگر شد متن لاگ را بفرست |
| `هیچ سرور زنده‌ای پیدا نشد` | نت رانر موقتاً محدود بود یا منابع down بودند | یک بار دیگر Run workflow بزن |
| ورک‌فلو در تب Actions نیست | مسیر فایل غلط است | باید دقیقاً `.github/workflows/post.yml` باشد |
| `failed to push` در مرحله کامیت | تداخل نادر با کامیت همزمان | مهم نیست؛ ران بعدی خودش ادامه می‌دهد |
| ران‌های خودکار اصلاً نمی‌آیند | ریپوی ۶۰ روز بی‌فعالیت غیرفعال می‌شود | نگران نباش؛ کامیت روزانه state جلویش را می‌گیرد |
| پست‌ها چند ساعت می‌آیند بعد قطع می‌شوند | ران قبلی در صف concurrency گیر کرده (با `cancel-in-progress: false` صف تا ابد بلاک می‌شد) | حل شد ✅ — الان `cancel-in-progress: true` است و ران بعدی رانِ گیرکرده را کنسل می‌کند |
| گیت‌هاب ران کرون را دیر اجرا می‌کند (۵ تا ۲۰ دقیقه) | رفتار عادی گیت‌هاب زیر بار است؛ ران‌های با تأخیر زیاد گاهی drop هم می‌شوند | طبیعی است؛ ساعت‌ها روی دقیقه 23/53 نیستیم تا کمتر پیش بیاید. پست چند دقیقه دیرتر در کانال ظاهر می‌شود |
| «کانفیگ‌ها از داخل ایران همه تایم‌اوت می‌دهند» | تا قبل از موتور Xray، تست فقط TCP بود: باز بودن پورت از آمریکا ≠ قابل استفاده در ایران؛ بخش بزرگی از کانفیگ‌های منابع عمومی در سطح پروتکل مُرده‌اند یا توسط فیلترینگ بلاک می‌شوند | ✅ حل شد با **موتور تست واقعی Xray** (بخش بعدی) + امتیاز ایران‌پسند + ساب کامل. هیچ تستی از بیرون ایران نمی‌تواند عبور از فیلترینگ را «تضمین» کند؛ برای همین ساب کامل را ایمپورت کن و با تست واقعی خود اپ سرور پیدا کن |

### 🔥 موتور تست واقعی Xray (ضد تایم‌اوت ایران)

ربات برای هر ۳۰۰ کاندیدای برتر (به انتخاب امتیاز ایران‌پسند) یک پروسهٔ واقعی
**xray** با پروکسی SOCKS لوکال بالا می‌آورد، تونل کامل پروتکل را می‌بندد
(TLS / Reality / VMess / Trojan / SS با همهٔ پارامترهای لینک: sni، pbk، sid، path،
host و…) و یک درخواست HTTP واقعی از داخل تونل رد می‌کند. فقط کانفیگ‌هایی که جواب
HTTP برگردانند «زنده» حساب می‌شوند و به پست یا ساب می‌روند.

نتیجهٔ واقعی (اولین اجرا): از ۳۰۰ کاندیدای TCP-سالم فقط **۷۶ کانفیگ واقعاً زنده** بود —
یعنی ~۷۵٪ همان کانفیگ‌هایی بودند که قبلاً پست می‌شدند و در ایران تایم‌اوت می‌دادند.
حالا پست‌ها فقط از بین تونل-تأییدشده‌ها انتخاب می‌شوند و سابسکریپشن هم فقط همین‌ها را دارد.

> ⚠️ صداقت: هیچ تستی از سرور خارج نمی‌تواند «عبور از فیلترینگ ایران» را تضمین کند
> (برای تست واقعی ایران باید پروب داخل ایران باشد). کاری که این موتور می‌کند:
> حذف قطعیِ کانفیگ‌های مُرده + ترجیح ساختارهای مقاوم (Reality و CDN کلادفلر).
> برای نتیجهٔ نهایی، ساب کامل را در اپ ایمپورت کن و با تست واقعی اپ (Ping/Real delay)
> از بین صدها کانفیگِ سالم، سرورهای قابل‌اتصالِ لحظهٔ خودت را پیدا کن.

### 🌍 تشخیص هویت واقعی سرورها (DNS + ASN) — جریمهٔ رنج‌های بلاک ایران

تجربهٔ میدانی می‌گوید فیلترینگ ایران رنج کامل برخی ارائه‌دهنده‌ها را بلاک/محدود کرده
است (شهرت‌ترین: **Oracle Cloud**؛ سپس DigitalOcean، Hetzner، Linode، Vultr و OVH).
ربات حالا برای بهترین کاندیداها اول DNS می‌گیرد، بعد با ip-api نام ASN/شرکت میزبان
را پیدا می‌کند: سرورهای Oracle تقریباً از انتخاب حذف می‌شوند (جریمهٔ ۴۵−)، بقیهٔ
ارائه‌دهنده‌های پرریسک به ته لیست می‌روند و سرورهای پشت **کلادفلر** (حتی با دامنه)
پاداش کامل CDN می‌گیرند. اگر ip-api در دسترس نبود، این مرحله به‌شکل امن رد می‌شود.

### 🗳 رأی‌گیری 👍/👎 اعضا — تنها معیار واقعی از داخل ایران

زیر هر پست دو ردیف دکمه هست: ردیف اول 👍 و ردیف دوم 👎 (شماره‌دار برای هر ۸ کانفیگ).
کاربران داخل ایران رأی می‌دهند و ران بعدی این رأی‌ها را با `getUpdates` می‌خواند،
به رأی‌دهنده جواب می‌دهد و در `state/feedback.json` ذخیره می‌کند. امتیاز رأی‌ها
(هر 👍 ۱۲+، هر 👎 ۱۵−، سقف ±۴۵) مستقیماً به ترتیب انتخاب پست‌های بعدی اضافه می‌شود —
یک حلقهٔ یادگیری ۹۰ دقیقه‌ای که کانال را با فیلترینگ واقعی ایران هم‌گام می‌کند.
پست آموزشیِ پین‌شدهٔ کانال (لینکش در `state/tutorial.json`) نحوهٔ رأی‌دادن و
تنظیم Fragment را هم به اعضا یاد می‌دهد.


### 🔍 ابزارهای تشخیص داخل ریپو (بدون نیاز به لاگ Actions)

| فایل | معنی |
|---|---|
| `state/last_run.json` | آمار آخرین ران موفق: چند کانفیگ پست شد، چند سرور زنده بود (وقتِ `ran_at`) |
| `state/error.json` | اگر رانی شکست بخورد، خودکار ساخته می‌شود و **چند خط آخر خروجی خطا** را دارد |
| `state/heartbeat.log` | ضربان‌سنج هر ۳۰ دقیقه (دقیقه ۷ و ۳۷ هر ساعت UTC) یک خط زمان اضافه می‌کند؛ اگر خط جدید نیامد یعنی کرون گیت‌هاب اصلاً اجرا نمی‌شود |

اگر پستی در کانال نیامد: اول `state/error.json` را در ریپو ببین (اگر هست، متن خطا داخلش است)؛ بعد `state/heartbeat.log` (اگر ضربان‌ها تازه نیستند، مشکل از زمان‌بندی گیت‌هاب است نه ربات)؛ در نهایت یک بار از تب **Actions → Run workflow** اجرای دستی بزن.

## 📱 استفاده از کانفیگ‌ها (برای اعضای کانال)

**v2rayNG:**
1. متن کانفیگ را از پست کپی کن (بخش بلاک کد).
2. در برنامه دکمه **+** بالای صفحه → **Import config from clipboard**.
3. سرور اضافه‌شده را انتخاب و وصل شو.

**NPV Tunnel:**
1. بخش **Config** → دکمه **+**.
2. کانفیگ کپی‌شده را **Import/Paste** کن، یا برای اشتراک دائمی از **Add Subscription** با یک URL استفاده کن.
3. بعد از افزودن: **Refresh → Ping → انتخاب سرور → اتصال**.

راهنمای مصور کامل (نقطه مرجع فاز ۲): ریپوی [mehrdadmb2/V2ray_Sub](https://github.com/mehrdadmb2/V2ray_Sub)

## 📡 سابسکریپشن اختصاصی امپرس (فعال شد!)

در هر ران واقعی، ربات تا ۳۰۰ کانفیگِ «تونل-تأییدشده» (تست واقعی Xray) را در این دو فایل ذخیره و کامیت می‌کند:

- نسخه متنی: `https://raw.githubusercontent.com/euphemiaa/empress-config-bot/master/state/sub.txt`
- نسخه base64: `https://raw.githubusercontent.com/euphemiaa/empress-config-bot/master/state/sub_base64.txt`

کاربر یک بار این URL را به‌عنوان Subscription وارد می‌کند و همیشه کانفیگ تازه دارد:

**v2rayNG:** برنامه → بخش **Subscription** → **+** → اسم دلخواه و بالا را Past کن → ذخیره → برای آپدیت روی آیتم بکش پایین (swipe refresh).

**NPV Tunnel:** برنامه → بخش **Subscriptions** → **+** → URL را Past کن → **Refresh** → لیست کانفیگ‌ها می‌آید.

> ❗ چرا فایل .npvt نمی‌گذاریم؟ چون فرمت فایل‌های .npvs/.npvt رمزنگاری اختصاصی خود اپ است (هدر NPVT1 + White-Box AES — بررسی و تأیید شد) و فقط پنل‌های خصوصی می‌سازندشان؛ ربات نمی‌تواند بسازدشان. در عوض هر پست یک **فایل پیوست `Empress-Configs.txt`** دارد (هر خط = یک کانفیگ) و سابسکریپشن هم رسماً توسط NPV Tunnel پشتیبانی می‌شود و بهتر از فایل هم هست: همیشه خودکار به‌روز می‌ماند.

## ⚙️ تنظیمات اختیاری (متغیرهای محیطی)

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `WORKERS` | 40 | تعداد نخ‌های تست TCP |
| `TCP_TIMEOUT` | 3 | تایم‌اوت تست به ثانیه |
| `CONFIGS_PER_POST` | 8 | تعداد کانفیگ در هر پست (بازه 1 تا 15) |
| `VLESS_COUNT` | 6 | سهم VLESS در هر پست؛ بقیه اسلات‌ها از بقیه پروتکل‌ها پر می‌شود |
| `PROTO_PRIORITY` | vless,vmess,trojan,ss | اولویت انتخاب پروتکل — پیش‌فرض اول بهترین VLESS را برمی‌دارد |
| `SUB_MAX_CONFIGS` | 100 | تعداد کانفیگ در فایل سابسکریپشن |
| `STATE_MAX_AGE_DAYS` | 10 | عمر حافظه dedupe به روز |
| `DRY_RUN` | 0 | 1 = فقط پیش‌نمایش |

> 🎯 این دو تنظیم را می‌توانی به‌عنوان «Variable» (نه Secret) در Settings → Secrets and variables → Actions → Variables هم بگذاری؛ ولی نیازی نیست، چون پیش‌فرض‌ها همان چیزی است که می‌خواهی.

## 🔐 امنیت

- توکن بات را **فقط** در Secrets گیت‌هاب نگه دار؛ هیچ‌وقت داخل کد یا README ننویس.
- اگر توکن جایی لو رفت، در BotFather با `/mybots → API Token → Revoke` توکن تازه بگیر و سکرت را آپدیت کن.
- ریپو می‌تواند Private باشد؛ ورک‌فلو و سکرت‌ها در ریپوی خصوصی هم کار می‌کنند.
